# Changelog

## Unreleased

- **Weighted criterion decomposition.** `select` and `compare` accept a complete
  `criterion_weights` mapping, and the new `swe_bench_logic` benchmark provides
  a fairly weighted L1–L6 ablation for Issue #1 with a separate score cache.
  Relative-weight aggregation rescales before summation to avoid overflow
  and underflow with very large or subnormal finite positive weights.
- **`dev` extra.** `pip install "llm-verifier[dev]"` pulls in pytest, the
  only dependency the test suite needs.

## 0.3.0 — 2026-10-08

- **Terminal-Bench 4.0 benchmark.** New `terminal_bench_4.0` benchmark: 330
  Claude Code / Opus 5.5 trajectories (max reasoning effort; 66 tasks x 5,
  from the Terminal-Bench 4.0.0 run; Pass@1 64.8%) verified by
  `deepseek-flash` (DeepSeek V4.1 Flash) at `DEEPSEEK_EFFORT=high` — a weak,
  cheap verifier judging a frontier generator.
  - Trajectories ship in `data/terminal_bench_4.0_trajs/`.
  - `scripts/run_tb4.0_bo3.py` and `scripts/run_tb4.0_bo5.py` reproduce the
    best-of-3 and best-of-5 results.
- **DeepSeek model id.** The verifier now calls DeepSeek's `deepseek-flash`
  endpoint (previously the pinned `deepseek-v4-flash`); that endpoint
  currently serves DeepSeek V4.1 Flash.
  - Nothing else about the backend changed — `DEEPSEEK_API_KEY`,
    `DEEPSEEK_EFFORT` and `DEEPSEEK_MAX_TOKENS` are unchanged.
  - The `terminal_bench_2.1` self-verification numbers were measured when the
    endpoint still served the `deepseek-v4-flash` that generated those
    rollouts, so a re-run judges them with the newer model.
- **Larger output budget.** `DEEPSEEK_MAX_TOKENS` now defaults to 65536 (was
  32768).
  - V4.1 Flash reasons more per call than V4 Flash did; on ~100k-token Claude
    Code traces the old budget left several percent of comparisons without a
    score.
  - `high` is the recommended effort for this endpoint.
- **Script naming.** The Terminal-Bench 2.1 reproduction scripts are now
  `scripts/run_tb2.1_bo3.py` and `scripts/run_tb2.1_bo5.py` (previously
  `run_bo3.py` / `run_bo5.py`).
- **Clearer error message.** A call that returns no score now says whether
  reasoning hit the output budget (`finish_reason='length'`) or the model
  stopped without an answer; previously both blamed the budget.

## 0.2.0 — 2026-08-14

- **DeepSeek verifier backend.** `deepseek-v4-flash` is now the default
  verifier when `DEEPSEEK_API_KEY` is set. Reasoning effort and output budget
  are configurable via `DEEPSEEK_EFFORT` (`off` / `low` / `high` / `max`,
  default `high`) and `DEEPSEEK_MAX_TOKENS` (default 32768).
- **Prefix-cache optimization.** Prompts keep the criterion at the tail and
  scoring warms one request per distinct prompt prefix before fanning out,
  raising the backend prefix-cache hit rate from 5.2% to 78.4% on
  Terminal-Bench 2.1 (~3.4× cheaper input).
- **Token accounting.** Every verifier call records input / cached-input /
  output / reasoning tokens in the process-wide `llm_verifier.USAGE` counter;
  `token_usage()` and `format_usage()` report per-run usage.
- **Self-verification benchmark.** New `terminal_bench_2.1` benchmark:
  mini-swe-agent trajectories generated by `deepseek-v4-flash` and verified by
  the same model.
  - `scripts/run_tb2.1_bo3.py` and `scripts/run_tb2.1_bo5.py` reproduce the
    best-of-3 and best-of-5 results standalone, each with its own score cache.
  - `scripts/run.py --n-trials N` truncates any benchmark to best-of-N.

## 0.1.0

- Initial release: fine-grained logprob reward, Probabilistic Pivot
  Tournament best-of-N selection (`select` / `compare`), progress tracking
  (`track` / `ProgressTracker`), multimodal inputs, benchmark runners for
  Terminal-Bench, SWE-Bench Verified, and MedAgentBench.
